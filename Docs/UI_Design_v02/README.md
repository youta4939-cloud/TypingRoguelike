# UIデザイン提案 v0.2 — AFTERLIFE / BLACK ENAMEL

2026-10-29。検討用の呼称であり、ゲームタイトルや世界観用語の決定ではない。v0.1の和風・平面的な方向性を引き継がず、既存パーツも参照しない。ゲーム本体の変更は行っていない。

## 今回の前提

- 現代風に発展した地獄。近代的な交通・施設・組織があり、その中に死と狂気が組み込まれている。
- 現代的なキャラクターデザインと共存する。
- Steam販売、日本語と英語の両方を最初から想定する。
- 欲しいのは装飾の少なさではなく、販売作品として納得できる画面全体の仕上がり。
- 既存パーツの形・素材・配色を継承しない。

## 「安っぽい」を作業できる言葉にする

以下はデザイン上の診断・提案であり、すべての市販ゲームに当てはまる法則ではない。

### 面が同じ高さに見える

同じ明るさの長方形を並べると、背景の上に箱を置いただけに見える。主役を手前に出す、表示面を奥へ沈める、隣の部品へ短い影を落とす、といった前後関係が必要になる。

修正指示の例：「選択中の入力プレートを、左右の候補より一段手前へ。左右は暗い溝に収める」。単なるドロップシャドウの一括追加では解決しない。

### 枠に輪郭しかなく、断面がない

一様な線だけだと厚みを感じにくい。光を受ける上辺、暗くなる下辺、面と縁の材質差を少量ずつ設計する。全周を同じ強さで光らせると輪郭だけが浮く。

修正指示の例：「上左の縁だけ細い反射。下右は暗い側面。文字にはその処理をかけない」。

### 材質の違いが色だけになっている

黒い塗装、透明な表示面、白いプレートが全部同じ反射なら、色違いの箱になる。反射の幅・ざらつき・透け方・エッジの鋭さを分ける。大きなノイズや傷を本文の後ろへ足すこととは違う。

修正指示の例：「筐体は低い反射、縁だけ鋭い反射、ガラス面は広く弱い反射。汚れは外周だけ」。

### すべてが同じ強さで主張する

全枠の発光、すべて大きい見出し、同じ大きさのカードが並ぶと、主役がなくなる。最初に見る場所を1つ決めて、明度・面積・文字サイズ・奥行きをそこへ集中させる。

このゲームでは入力中の文字が主役。敵の次の攻撃、HP・狂気、装備の順に視線が移る構図を出発点にする。

### 画面固有の形がない

汎用ボタンを並べた画面は、配色を変えても別のゲームに見える。ここでは「切れ目と赤い指標を持つ円形ソケット」と「入力プレートを収めた一体の装置」を共通の造形にする。すべての角を切り落とすだけでは独自性にならない。

### 文字が装飾の後から載っている

フォント・改行・数字の桁揃え・内側余白もUIの造形。まず文字が収まる形を設計する。英語が長くなるたび縮小する作りにはしない。

### 静止画と動作の品質を混同する

美しい1枚だけでは販売作品のUI品質は確認できない。フォーカス、押下、無効、長文、入力ミス、危険状態、画面遷移まで同じルールで仕上げる必要がある。

## 新しい方向性

地獄の現代的な組織が使う、上質で不穏な業務用装置。黒い焼付塗装、スモークガラス、薄いチタン色の縁、生成りの操作プレート、深い赤の内部材を組み合わせる。

「豪華」は金色の装飾量ではなく、部品同士の納まり、光の整合、触ったときの反応を想像できることに置く。UIを背景から外して見ても、部品単体に仕上がりがあることを目標にする。

一般的な青いSFホログラム、古い時代の和風、トゲ付きの中世ゴシック、全面クロームの機械には寄せない。これらはユーザーの世界観を狭めないための今回の制作上の制約。

## 管理する共通ルール

### 材質は3種類

1. 筐体：黒い半艶の焼付塗装。大きな面に弱い光の変化。
2. 表示面：奥に沈んだスモークガラス。文字の周囲は静かに保つ。
3. 操作面：明るいセラミック調。確定・選択中など、重要な操作だけに使う。

金属は材質4種類目の大面積パネルにせず、縁と接合部に限定する。発光は状態を示す小さな指標と演出に集中させる。

### 光と奥行き

UI部品の仮想光源は上左に固定。シーン背景の光で文字の見え方を毎回変えない。

前後は、筐体・沈んだ待機面・手前の選択面の3段階を基本にする。1920×1080を基準に、縁の反射は1〜2px、部品間の段差表現は2〜6px、接触影は短くする案。数値は実装テストで調整する。

大きな外側のぼかし影を全パーツへ付けない。装飾と反射を、本文の上へ重ねない。

### ボタン

主操作は明るい操作プレート、副操作は暗い表示面。通常・ホバー・フォーカス・押下・無効・危険操作を共通部品として作る。

- 通常：細い上辺反射と短い下影。
- フォーカス：赤い指標が所定位置へ移動し、面が少し明るくなる。
- 押下：段差と下影が縮まり、実際に押し込まれたように見える。
- 無効：彩度・反射を弱め、実行できない理由を添える。文字を読めないほど暗くしない。
- 危険操作：赤い内部材と警告記号で区別する。

同じ画面で全部のボタンを主ボタン扱いしない。ボタン高さの出発点は56px、本文サイズ24px、左右内側余白24px。

### テキストフレーム

大きな台詞・イベント枠には、筐体の外周、内部の表示面、名前の小さな操作プレートを使う。本文は一番静かな面に置く。ガラスの反射は枠の外周に薄く残し、文字が入る中央には被せない。

タイトル、本文、結果説明、選択肢を明確に分ける。枠画像に文字を焼き込まない。名前欄と選択肢は長い英語を置いて確認する。

### 文字

本文は日本語ゴシック／ラテンのサンセリフ、入力は等幅。装飾書体は見出しに限定する。和風を示す書体は共通部品の前提にしない。

数字は桁揃え。入力文字は最大の可読要素とし、活字に金属やエンボス加工をかけない。生成画像の英字の形やカーニングは採用フォントの最終見本ではない。

### 色

暫定トークン：筐体 `#17191C`、表示面 `#22262D`、本文 `#EEE9DF`、金属縁 `#90979F`、内部の深赤 `#4A2029`、警告 `#EF5948`、狂気 `#A597D0`。

オーブ5色は属性識別に保持するが、枠全体を属性色で囲まない。各色に形の違いも与える。狂気と紫オーブはラベルと形で区別する。

### 演出

入力の反応は即時。ホバーは約100〜140ms、押下の沈みは約60〜90ms、パネル遷移は約180〜260msを初期検討値とする。常時揺れる文字や入力面の追従移動は行わない。

狂気が増すと表示面の外縁に異常が現れる案。文字領域へノイズを流さない。ジャックポットは蓄積された光と赤い指標が装置の継ぎ目から解放される演出にし、通常時との差を作る。閃光や揺れを軽減できるようにする。

## 日本語・英語

同時に2言語を表示する画面にはせず、それぞれで自然な情報量にする。メイン画像は英語版で作り、英語が装飾の脇役にならないことを確認する。日本語版では同じ構造へ日本語を置く。

入力する問題の言語とUI言語は別の仕様。画像内の `verdict` などは入力領域のデザインを評価する仮の問題で、英語版に英単語問題を採用する決定ではない。未決定の英語版タイピング方式は別途検討が必要。

長文は最初に折り返しや拡張で吸収し、文字サイズの縮小を最後の手段にする。1366×768と1920×1080、長い敵名・スキル名、各状態の読みやすさを確認する。

## 提供されたイベント実画面の診断と改案

`00_event_before.png` はユーザー提供の画面。仮の参考素材よりも、この実画面の課題を優先する。

見た目の課題は、イラストの縦横比が崩れて見えること、本文が横1行で切れていること、本文・イラスト・選択肢をそれぞれ独立した大きな矩形にしていること。金色の同じ線で全部を囲むため、重要度の差も弱い。絵の中は焚き火で休む場面だが、本文は崩れかけた通路を急ぐ場面で、内容も噛み合っていない。

判断の課題は、塔片+20が両方の結果で重複し、確率ごとのHP損失を比較しづらいこと。現在HP103に対してHP150を失う結果が40%ある。通常のダメージ適用なら戦闘不能になるので、選択前にその危険を明示する提案。

改案では、左に比率を保ったイベント絵、右に本文と縦積みの2択をまとめる。絵は現代の地獄の通路が崩れそうな場面として新規制作。物語の意味を変えず、見切れていた本文は完結する文章へ整える仮案であり、原文の完全な復元ではない。

選択肢の意味は維持する。「袋を拾って走る」は塔片+20を共通報酬として一度示し、60%でHP−50、40%でHP−150を揃えて表示。「まっすぐ駆け抜ける」は100%変化なし。現在HPと損失の比較を助ける警告を追加する。選択肢に新しい効果や信頼増減は追加しない。

装飾だけでなく、画像表示の縦横比維持、本文の折り返しと高さ、レイアウトの一体化を直すことが優先。絵は枠の都合で引き伸ばさず、比率を保ち、必要に応じて意図した範囲でトリミングする。

人物名は従来のアリス・エレン・ルナを仮名として使う。提供画面のアカネ・モモ・ナギから名称を変える決定ではない。素材表示は廃止方針に合わせて提案から外す。

複数タイトルの「かっこいい部品」を寄せ集めない。今回の材質・光・形のルールへ翻訳して制作する。

## 品質の判定方法

戦闘の生成案は、質感の差を分かりやすく示すため、金属の筐体が重めになっている。部品ガイドはそこから構造を薄くする方向を示す。最終実装では細かなネジ・傷・フレームを減らしても、上辺反射・段差・接触影を残すことで奥行きを保つ。生成された2枚がピクセル単位で一致する部品仕様ではないことに注意する。

まず背景を外した部品だけで、厚みと状態差が残るかを見る。次に背景を戻し、入力文字・予告・HPと狂気の順に視線が動くかを確認する。

通常・長文・低HP・狂気臨界・ポーズ・無効ボタンを同じ品質で揃える。最後に日本語と英語の実際の文字、アニメーション、効果音、入力遅延まで確認する。

今回の画像は高品質な完成像を探るコンセプトであり、市販品質へ到達したと保証するものではない。実装用には背景から独立した素材、9-slice、フォント、状態ごとのプレハブ、演出が必要になる。
