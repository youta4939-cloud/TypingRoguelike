# 探索3画面のUIコンセプト

作成：2026-10-29。ユーザー提供の「ルーレットビルド」「マス抽選」「その層のマス」を、イベント画面提案と同じデザイン言語へ展開する資料。ゲームコードの変更は行っていない。

## 共通の見た目

黒い半艶の面、奥に沈んだ表示部、薄い金属の縁、生成りの選択面、赤い小さな指標を共有する。イベント画面の質感を使うが、全画面を同じ左右分割にはしない。

色・文字・アイコンは同じ機能に同じ意味を持たせる。各マスの絵柄は、ビルド中の盤面、抽選中のリール、確定後のカードで共通にする。例ではイベントを現代的な記録・メッセージの図柄へ変更しているが、最終アイコンの決定ではない。

画面上部の層表示、編成／抽選／探索の段階表示、通貨の位置を揃える。下部にはHP・狂気・仲間を置く案。ステータスの値は初層の仮表示であり、実行中のゲームを再現したものではない。

戦闘では入力付近への情報集中を優先するため、戦闘HUDをこの下部帯へ強制的に変更する提案ではない。

## 01 ビルド：考えて編集する画面

左から「使える欠片」「編集中の盤面」「盤面によって生まれる確率」。視線の流れを操作と一致させる。

中央は3列×6行を明確にする。パーツが複数マスを占めることは、左の小さな形状見本と配置時のまとまったハイライトで伝える。選択中の欠片を動かすと、対象列の確率だけが短く更新される演出が考えられる。静止画では操作を検証していない。

列ごとの確率は文章の羅列だけでなく、同じ場所に揃えた割合表示と短い棒で示す。0%の役をすべて常時展開するのではなく、「主な役」と「すべて見る」に分ける案。詳細情報を削除する決定ではない。

例示盤面は提供画像に合わせ、上から BBB / EEE / EEE / BRS / EEE / BBB。列ごとの戦闘数は3、2、2。最低条件は各列2。戦闘×3は5.56%、イベント×3は12.50%となる。画像内の細かな数値に生成誤りがあれば、この記述を参照する。

「この記憶で進む」は確定操作として右下に置く。必要条件を満たさないときは、そのボタンだけでなく不足列にも理由を表示する。

## 02 抽選：結果を楽しむ画面

ビルドで見ていた3列が、そのまま3つのリールになる構成。中心線は結果を読む位置として固定する。

確率の説明は脇の小さな領域へ移し、中央のリールを大きくする。初回の長い説明は開閉式や初回案内へ移す案。通常時には「回転→左から停止→確定」の短い段階表示で十分かをプレイで確認する。

画像では途中状態として、左2列は確定、右列は抽選中を想定する。スタート・抽選中・確定後の操作ボタンは同じ場所で状態を切り替える。演出スキップは抽選結果を変えない。

4マス目は抽選対象と分け、「固定：強敵」として示す。第1層の例なので、エレベーターやボスにはしない。

## 03 その層のマス：選んだ道を読む画面

大きな絵入り4枚の構成は活かす。上の01〜04と細い接続線で順番を示し、最初の3枚と固定の4枚目を区別する。

現在地は明るい操作面と小さな指標、未到達は状態ラベル、固定強敵は深い赤と固定ラベルで示す。広いオレンジのぼかしや背後の不透明な矩形は使わず、選択枠に近い短い光で質感を出す。

文字はフレーム内の専用領域に収める。「進む」をカードの見出しと重ねず、押せる場所として明確にする。イラストは縦横比を保ち、カード枠に合わせて意図的に切り取る。

イベントが2枚続いても画像を変えることで場面の反復感を弱める案。ただし未到達の時点でイベント内容を明かすかどうかは別の仕様判断であり、汎用カテゴリ絵を使う方法もある。画像中の人物・敵・台詞は仮。

## 画面のつながり

編成確定後、盤面の3列が抽選窓へ変わる。抽選で止まった3図柄が縮小・展開され、道の最初の3カードへ移る。4枚目は固定枠として現れる。これで「何を組んで、何が選ばれ、どこへ進むか」が視覚的に繋がる。

遷移演出は入力を長く拘束しない長さにし、スキップや演出軽減も検討する。この動きは提案であり、今回の静止画には実装していない。

画像は構成・質感のサンプルで、文字・数値・アイコンや部品位置が厳密に一致する設計図ではない。実装用には共通部品、実フォント、状態差、日英の長文、ドラッグ中の表示を別途制作・確認する。

画像内の欠片一覧は代表例のみで、提供画面の「特殊・戦休店」などを省略している。機能廃止を意味しない。実装ではスクロールやカテゴリ分けで全件へアクセスできるようにする。また役の確率の棒の長さは生成画像の表現であり、厳密な比例は保証しない。実装時は共通スケールに揃える。

生成画像のイベントアイコンはビルドと抽選で一致していない。実装では必ず同一素材へ統一する。抽選画面の役の確率は抽選前の盤面に対する値であり、途中まで停止した結果に応じた条件付き確率ではない。その意味をラベルで明示するか、抽選開始後は隠す案とする。

道の画像ではHP満タンでもゲージが赤く生成されている。共通ルールでは満タンは生成り、危険時のみ赤へ統一する。細かな色・素材の違いは今回の画像案をそのまま採用せず、共通部品で解消する。
