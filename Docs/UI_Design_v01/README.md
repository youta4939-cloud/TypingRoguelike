# UIデザイン提案 v0.1 — 獄の記録

作成：2026-10-29。採用前の提案であり、ゲーム本体のUIは変更していない。

## 狙い

地獄庁の帳簿・封印札を共通の造形にする。墨色の面、生成りの文字、くすんだ真鍮の細線を基本とし、キャラクターと背景イラストを引き立てる。装飾量よりも、文字の読みやすさと情報の優先順位で質感を作る。

調査した参考画像は `battle_E5b_parts/recompose_E5b.png` と `rlb_v1/Reference/route_02_final.png`。現在実行中のゲームのスクリーンショットではない。コードでは `BattleUITheme.cs` に赤系・ガラス系・紫のスタイルが併存している。参考画面では金属装飾、発光、宝石、太い文字縁取りが重なり、目立たせたいものの優先順位が揃っていないと判断した。

## 色のルール

- 背景：`#121416`。
- パネル：`#202427`。本文の背後は不透明に近い面を置く。
- 本文：`#E9E1CF`。
- 選択・フォーカス：`#A68B5B`。長文には使わない。
- 危険・敵攻撃：`#C94F45`。
- 狂気：`#9A88BA`。

赤・青・黄・紫・緑の5色はオーブの属性識別に使う。青い枠は味方、金の枠は初期刻印など、枠色に別の分類を重ねない。属性は色だけでなく形でも区別する。

## 文字と寸法

1920×1080を基準にする。見出しは明朝、本文と操作はゴシック、ローマ字入力は等幅。フォントは各用途1系統に絞り、プロジェクト内の既存フォントからライセンスと実際の収録文字を確認して選ぶ。

提案値：大見出し40px、本文24px、補助20px、入力44px。本文の行間は1.6。余白は8pxの倍数とし、パネル内側24px、関連要素間16px、セクション間32px。小さい補助文字を増やす前に常時表示の必要性を見直す。

実装時は1280×720相当でも確認する。入力文字の判別性を最優先にし、本文を暗い背景に重ねてコントラストを測定する。生成画像をもって可読性の検証完了とはしない。

## フレームとボタン

フレームは平らな暗色面と細い1本の線を共通部品にする。外形は小さな角落としで統一。封印モチーフは見出しや大きなモーダルに1つまで。本文枠にトゲや大きな金属飾りを付けない。

ボタンは高さ56px以上、左右余白24pxを基本とする。1画面で主ボタンは原則1つ。

- 通常の主操作：生成りの塗りと墨色の文字。
- 副操作：暗色の塗りと細線。
- ホバー・キーボードフォーカス：小さな菱形の印と明るい内側線。色だけで区別しない。
- 押下：面を少し暗くし、内側の影で押されたことを示す。
- 無効：彩度を落とし、鍵アイコンや「塔片不足」など理由を添える。
- 取り返しのつかない操作：朱色と具体的な動詞を使う。すべての主ボタンを赤にしない。

共通部品として `Frame/Default`、`Frame/Dialog`、`Button/Primary`、`Button/Secondary`、`Button/Destructive` を管理し、状態を各画面で作り直さない。枠はUnityの9-sliceを前提とし、文字は画像に焼き込まない。

## 戦闘画面の優先順位

第1優先は入力中の単語、第2優先は敵の次の攻撃と残り時間、第3優先は共有HPと狂気。背景とキャラクターはその後に置く。

単語候補は中央下に3枚。すべて同じ形のカードにし、選択中だけ明確に強調する。入力済み・未入力は明度と下線で識別し、単語の色は小さな属性印で示す。候補を三角形に散らしたり、敵の輪郭に文字を重ねたりしない。

敵の攻撃予告は名前と残り秒数を同じ場所に表示する。共有HPと狂気は下部の固定帯で隣接させる。狂気の危険段階は文字でも示す。オーブ列は入力候補の直下。装備スキル9枠は左の一定幅の欄に揃え、各人3枠の位置を固定する。

ジャックポット確率の計算内訳や詳細ステータスは常時の大表示から外し、詳細画面で確認できるようにする案。仕様上の情報を削除する決定ではない。

## 演出

通常時は静かにする。ボタンの反応は約120ms、パネル切り替えは約180msを出発点にする。入力への反応は即時。常時の発光・揺れを重ねない。強い閃光や大きな画面演出はジャックポットなどの節目に限定し、演出軽減設定を用意する案とする。

## 次の制作工程

方向性が固まったら、フレーム・ボタン・アイコン・ゲージをそれぞれ分割制作する。共有トークンとUnityプレハブを作り、まず戦闘画面1つで実際の入力・読みやすさを確認してから、リール・出来事・店・拠点へ広げる。

今回の画像は組み込みのImageGenで作成。再生成用プロンプトは同フォルダの `prompts.json`（ガイド）と `prompt_battle.txt`（戦闘画面）に保存する。戦闘画面内のキャラクター・敵・背景は方向性を伝える仮のイラストで、既存素材の差し替えやキャラクターデザインの決定を意味しない。
