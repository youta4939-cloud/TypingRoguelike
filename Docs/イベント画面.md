# 出来事画面のレイアウト

更新: 2026-11-14

画面の見た目は `Assets/_Project/Resources/UI/StoryEvent.prefab` に保存する。
`LayerPathUI.StoryPrefab.cs` はイベントの文章・数値・画像・操作だけを結び付け、保存した配置・フォント・色を上書きしない。今回の移行対象はイベント画面のみ。

- 共通の和風廊下を全面に敷き、上段に大きな明朝体のタイトルと本文を左揃えで表示する。本文背後は横方向の暗いグラデーションで読みやすくする。書類・報告書・イベント別の挿絵は使わない。
- 背景 `Resources/Run/Path/bg_story_corridor.png` は縦横比を維持して画面を覆う。未設定なら既存の廊下画像にフォールバックする。
- 下段は同じ大きさの選択肢を二列に置く。確率は専用列に置き、各効果は自然な高さで積む。戦闘条件と「勝利後」の報酬を区別する。
- メリットの数値・単位は青緑、デメリットはくすんだ朱色、狂気の増減は紫。説明文と確率は生成り色のまま。符号だけで判定せず、敵HPの減少などはメリットとして扱う。
- 選択肢ごとに下端へ3人分の固定欄を確保する。0人でも空間を維持し、上・横の区切り線や「仲間の推し」ラベルは置かない。実際に賛同した者だけを表示し、好感度効果の予告だけのキャラは入れない。
- スタンプ未整備のため、好感度欄と同じ顔スプライトに名前・既存の意見セリフを添えて代用する。キャラIDを優先して照合し、顔画像を共有する。
- 本文、仲間の遠慮、選択肢の効果、長い意見セリフはスクロール可能。フォントや行間を押し潰さない。スクロールバーは内容が収まる場合、プレビュー・プレイ共に隠す。
- ホバー／キーボード選択は細い鈍い金色の枠だけを明るくする。移動・拡大・点滅・面全体のハイライトはしない。
- 下部左にHP・狂気、右に3人の顔・名前・現在好感度を表示。ホバー／選択フォーカス時に、好感度の右の固定幅欄へ実際の予告差分を表示し、解除で消す。現在値自体は変えない。サンプルの「+5」を固定で付けず、既存の性格設定とイベント効果から計算する。
- 選択後は両方のボタンを無効化し、同じ画面の選択を二重に処理しない。
- 結果ダイアログも、本文と操作ボタンを分離したスクロール領域にする。

出来事画面は保存済みPrefabをインスタンス化する。固定要素を削除・再生成しない。本文・意見セリフはTextMeshProの日本語禁則処理で句読点の行頭折り返しを避ける。

## Unityでの編集

1. Projectで `Assets/_Project/Resources/UI/StoryEvent.prefab` をダブルクリックする。
2. Hierarchyで要素を選択し、Rect Transform、Text / TextMeshPro、Imageで位置・サイズ・文字・色を調整して保存する。
3. プレイし直すと、全イベントに変更が反映される。再生中のインスタンスではなくPrefabを編集する。

タイトル等でBest Fitが有効な場合、最大の文字サイズはMax Sizeで調整する。固定サイズにしたい場合はBest Fitを解除してFont Sizeを設定する。

主な要素:

- `EventTitle`：タイトル。`TitleAccent`：下の短い金線。
- `BodyPlate`：本文領域全体。`Narrative/Viewport/Content/Body`：本文のフォント・行間。`Aside`：補足。
- `Choice0` / `Choice1`：左右の選択肢。`Label`：見出し。`TitleRule`：見出し下の線。
- `ChoiceDetails/Viewport/Content/EffectRowTemplate`：効果行のテンプレート（通常は非表示）。`Effect`：効果の文字設定。`Chance`のLayout Element：確率列の幅。行のHorizontal Layout Group：横間隔。
- `OutcomeGapTemplate`のLayout Element：抽選結果間の縦間隔。ContentのVertical Layout Group：効果行の間隔。これらは自動レイアウトなので、各行を直接ドラッグする代わりにLayout Group / Layout Elementを調整する。
- `SupporterLane/SupporterSlot0～2`：3人分の固定欄。`Face`：顔の配置。`SupporterName`：名前。`SupporterSpeech`：セリフの領域。
- `StatusBar`：HP・狂気・好感度。`AffinitySlot0～2`：各キャラ。`AffinityDelta0～2`：ホバー時の差分欄。
- 選択肢の `EventChoiceHover` コンポーネント：通常時と選択時の枠色。
- `Backdrop/Picture`：背景の画像・色。`ReadingShade`：暗いグラデーションの濃さ。

ルートの `StoryEventPrefabView` に各要素の参照を保存する。名前変更や親変更でも参照は保持される。要素を削除・置換した場合は対応する参照をInspectorで再設定する。

効果行は非表示テンプレートを複製する。テンプレートの確認のため一時的に表示しても、保存前に非表示へ戻す。文章・現在値・顔画像はイベントデータで差し替わる。メリット等の数値色は `EventText` の意味別設定を使う。

初回移行メニューは `Tools > TypingRoguelike > Migrate Event UI To Prefab`。移行済みPrefabは再実行しても上書きしない。一般の `Build Screen Prefabs` もイベントPrefabの手動調整を保持する。コード内の生成メソッドは初期作成・検証用で、通常プレイでは使わない。

## 検証

Unityメニュー `Tools > TypingRoguelike > Check Event Layout` を実行する。

未保存のシーンを保存・再読み込みしたくない場合は、`Tools > TypingRoguelike > Preview Event Layout Without Scene Switch` を使う。同じ15項目の描画・操作アサーションを同期実行し、自分が作成したUI・カメラ・EventSystemだけを破棄する。結果は `Logs/StoryEventLayout/direct-checks.txt` に保存する。

`StoryEventLayoutTests` は、全イベントの本文の収まり、4種類の解像度・縦横比、長文と大量の効果の末尾へのスクロール、結果本文とボタンの分離、選択の一度限りの実行、3人分の固定欄と画像共有、ホバー・キーボードの好感度予告、数値の意味による色分けを検証する。Prefab版を4種類の解像度・縦横比で確認する。Prefabを変更した配置・フォント・色、効果行テンプレート設定の保持、欠落スクリプト、画像・フォントの永続参照も確認する。

プレビューPNGと結果XMLは `Logs/StoryEventLayout/` に生成する。生成画像はUnityのUIをカメラで描画した確認用であり、ゲームの進行状態を変更しない。

## イベントへの遷移

プレイ中は `StoryMistTransition` により1.2秒の暗い靄を表示する。前画面は靄が不透明になるまで保持し、中間点でイベントに交換する。unscaledDeltaTimeで進行し、終了までCanvasGroupと全面の入力ブロッカーで誤操作を防ぐ。中断時も前画面・靄を破棄する。128pxのシームレスノイズを一度だけ生成して共有し、毎フレームの画像生成は行わない。編集時の静止画プレビューには演出を適用しない。

靄は `Resources/Run/StoryMist.shader` で二層の雲模様を合成する。青灰色の濃淡を付け、ノイズに沿って不均一に覆う・晴れるため、単なる黒フェードにならない。マテリアルは遷移終了・中断時に破棄する。
