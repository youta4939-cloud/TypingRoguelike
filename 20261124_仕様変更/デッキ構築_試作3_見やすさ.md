# Cursor指示書：デッキ構築 試作3（何を打てばいいか分かる画面）

作業ブランチ：`feature/deckbuild`。試作2（バグ修正＋手札UI）の後に行う。社外秘。
試しに遊んだ結果、「何を打てばいいか分からない」「手札が画面の下いっぱいで目の移動がきつい」が出たので、その改善。

## 1. 単語カードに「打つと何が進むか」を出す（最優先）
単語を打つとその単語の色のオーブが1つ増える。そのとき手札のカードがどうなるかを、単語カードの下に1行で出す。

### 判定（単語ごと、手札の各カードについて）
- 「今のオーブ列＋この単語の色」の末尾が、カードの色の並びの**先頭から何色ぶん一致するか**を調べる（一致した長さ＝j、カードの色数＝n）。
  - 末尾の取り方：長さ j の一致は「オーブ列の末尾 j−1 個＋この単語の色」がカードの先頭 j 色と同じ、で判定する。j は n から 1 まで大きい順に試し、最初に一致した j を使う。
- j = n → **発動**。j < n → **あと n−j**。j = 0 → そのカードは表示対象外。

### 表示（彩木さんの案）
- 判定は単語ごとに「カード名（・の前の技名）、状態（発動／あとN）、種類、手札の位置」の一覧として返す関数にする（UIはそれを並べるだけ）。
- 単語カードのすぐ下に、小さな札を**最大2行**出す。
  - 並び順：①発動するもの（バフ→シールド→攻撃の順、同じ種類は手札の左から）→②あとNが小さいもの（同じなら手札の左から）。
  - 発動は `→居合い斬り 発動`（カードの色で光らせる）、それ以外は `→斬撃 あと1`。
  - 3件以上あるときは、2行目の右端に `+n`（残りの件数）を付ける。
- その単語にカーソルが乗っているか、打ち始めた単語については、一覧に入っている手札のカードを光らせる。
- 何も進まなければ札を出さず、単語カードを少し暗くする（明るさ70%）。
- 長い名前は自動で縮小。表示はオーブ列と手札が変わるたびに更新し、判定はロジックだけで即時に行う（演出を待たない）。

### 確認
- オーブ列が空で、手札に斬撃・紅蓮（赤赤）がある → 赤い単語に `→斬撃 あと1`。
- 赤を1つ打った後 → 赤い単語に `→斬撃 発動`。
- 手札のどのカードの先頭色でもない色の単語は、暗くなって何も出ない。

## 2. 画面の配置（彩木さんのC案：手札3枚・1.2倍）
見た目は彩木さんの `cursor_pack_v6C.zip` に合わせる。
- `reference/` のモック（mock_v6_C.png と拡大版）の見た目に合わせる。モックのカードの色の並びや状態は見本なので、色は cards.csv の値を使い、状態は1章の判定で出す。
- パーツは `parts/` の透過PNGを使う。重ねる順番と文字の位置は `README_parts.md` と `layout_parts.json` に従う。
- 座標は `layout_v6.json` の `mocks.C` を正とする（1920×1080基準）。以前の試作2の0.75倍やA案・B案は使わない。`HandLayoutVariant` の切り替えも作らない。

主な数値（mocks.C より）：
- **単語カード**：250×112、間36px、中央そろえ、上端 y592（下端 y704）。
- **ヒント**：1行目 y712、2行目 y742、高さ26、最大2行、あふれは「+n」。下端は y768。
- **前の色 / STOCK**：単語の右のパネル（x1392〜1666、y596〜700）。
- **手札**：**3枚固定**、1.2倍（376×180）、間20px、x376〜1544 で中央そろえ。休んでいるときの上端は y880（下端 y1060）。
  - 持ち上げ：あと1色 +17、条件成立 +34。大きさは変えず、持ち上げるだけ。
  - 文字：名前34px、効果24px、タグ22px。
  - 宝石・タグ・×Nバッジの位置は、手札カードの1倍の値（README_parts.md）を1.2倍にする。mocks.C の cards[].tag / gems が見本の座標。
- **敵**：x810〜1131、y114〜584。**攻撃タイマーの円**：中心 (600,330)。**Extra Area**：x1540〜1830、y240〜486。
- **ログ**：右下（x1600〜1904、y840〜1060）。
- HP/SAN・顔アイコン・山札/捨て札・シールドは左下のまま（x10〜258、y776〜1076）。

## 3. 手札は常に3枚
- 手札の上限を設定1か所にする（`DeckConfig.HandSize = 3`）。チュートリアルを含め、全部の層で3枚。
- 補充は「上限未満なら上限まで」。
- 試しに枚数を変えられるよう値は1か所にまとめるが、UIは3枚の配置だけ作ればよい。

## 3.5 初期デッキを10枚にする（手札3枚用、仮）
手札が3枚だと山札の一周に時間がかかり、3色の居合い斬りもなかなか手札に来ないので、12枚から10枚に減らす。starter_deck.csv を次の内容にする。

```csv
card_id,count
slash_r,2
slash_b,1
thrust,1
guard_g,2
guard_b,1
stance,2
iai,1
```
（7種・10枚。同じカードは2枚までなので、合体で山札が空になることはない。試作2の枚数チェックは10枚で通ること。）

## 4. 確認方法（まとめ）
1. どの層の戦闘でも、手札が3枚・1.2倍で、単語の下の中央に並ぶ。
2. 単語カードの下に「→〇〇 発動」「→〇〇 あと1」が出て、打つたびに更新される。
3. 画面が reference のモックとほぼ同じ見た目になり、ヒント・タグ・カードが重ならない。
4. 試作2の枚数チェックが、初期デッキ10枚で Console のエラー無しに通る。
