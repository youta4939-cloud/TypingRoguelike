# Cursor指示書：デッキ構築 試作4（戦闘後のカード獲得画面）

作業ブランチ：`feature/deckbuild`。試作1〜3の後に行う。社外秘。Unity 6000.3.25f1。
数字はすべて仮。あとで定数やCSVだけで差し替えられるようにすること。

## 目的
デッキモード（`GameModeConfig.UseDeckMode = true`）で戦闘に勝ったら、**「カード2枚」と「塔片」の3つから1つ**を選ぶ画面を出す。
- カードを選ぶと、ランのデッキに1枚加わる。
- カードをクリックすると、**今のデッキとのコンボルート**がそのカードの下に出る。
- 直前2回の画面に出たカードは、候補に出さない。

`UseDeckMode = false` のときは、今までの刻印報酬（`RunOverlayUI.ShowCardReward`）のまま動くこと。古いコードは消さない。

## 1. 今のコードの流れ（ここに差し込む）
- 勝利：`RunFlowController.OnBattleVictory()` → 通常戦は `CombatVictoryRoutine()`、ボスは `BossVictoryRoutine()` → どちらも `OfferCardReward(notice, onFinished)` → `ShowPendingCardReward()` → `_overlay.ShowCardReward(...)`。
- 報酬の後は `FinishCardReward()` が `CompleteNodeAndReturnToMap()` か `onFinished` を呼ぶ。**この終わり方はそのまま使う。**
- 塔片はすでにある：所持は `RunPartyState.RunCoins`（`_party.AddCoins(n)` で増やす）、保存は `MetaProgressData.towerRunCoins`。戦闘の基本量は `GrantCoinsForCurrentBattle()`（通常8・エリート15。役やレイヤーの倍率込み）。

### 変更点
1. `OfferCardReward()` の先頭で、デッキモードなら新しい `OfferDeckReward(notice, onFinished)` を呼んで return する（宝箱マスの「刻印を選ぶ」も同じ画面になる）。
2. `OnBattleVictory()`：デッキモードでは `_party.AddCoins(coins)` を**しない**（塔片は3択の1つとして受け取る）。
3. 通知文はデッキモードでは「戦闘に勝った。カードを1枚選ぶか、塔片を受け取る。」にする。
4. 選び終わったら `PersistActiveRun()` を呼んでから `FinishCardReward()`。

## 2. 塔片の量（仮）
`DeckRewardConfig`（定数クラス、1か所）にまとめる。

```
塔片 = 基本量 × CoinMultiplier ＋ 層 × CoinPerFloor
  基本量        = GrantCoinsForCurrentBattle()（ボスは dungeonRun.eliteCoinReward）
  CoinMultiplier = 2   // 仮
  CoinPerFloor   = 2   // 仮。層 = _dungeon.Floor
```
例：1層の通常戦 8×2＋2＝**18**、10層の通常戦 8×2＋20＝**36**、10層のエリート 15×2＋20＝**50**。（商人の回復10、レリック60と比べるための仮の値）

## 3. 候補の選び方（`DeckRewardPicker`、新規の static クラス）
1. **母集団**：`Resources/Deck/cards.csv` の全カード。
   - cards.csv に任意の列 `reward` を足せるようにする（`0` なら候補にしない）。列が無い、または空なら `1` とみなす。
   - **デッキに同じカードが既に3枚あるものは除く**（試作1の「デッキ内の同名は最大3枚」を守るため。重なりはLv3まで）。
2. **履歴**：直前2回の画面で出したカードidを除く。
3. 残りから**違うカードを2枚**選ぶ。重みは `DeckRewardConfig.RarityWeight`（`N=1, R=1, SR=1`。今は全部同じ。あとで変える）で抽選。
4. **足りないとき**（残りが2枚未満）：まず**古いほうの画面**の除外を外して選び直す。まだ足りなければ、新しいほうの除外も外す。それでも足りなければ、出せる枚数だけ出す（1枚や0枚でもよい。塔片は必ず出す）。3枚上限の除外は外さない。
5. **履歴の更新**：画面を出した時点で、その画面のカードidを履歴の先頭に入れ、3つ目以降は捨てる（**塔片を選んでも1回と数える**）。
   - つまり、ある画面に出たカードは次の2回には出ず、3回目からまた抽選に入る。

### 保存
- 履歴は、ランの間ずっと持つ（戦闘をまたぐ。エレベーター帰還でも消さない）。
- `MetaProgressData` に `towerRunRewardHistory`（例：`List<string>`。1要素＝1画面ぶんのidを `,` でつないだもの。最大2要素）を追加し、`SaveActiveTowerRun` で書き、ラン再開時に読む。`ClearActiveTowerRun` で空にする（全滅・踏破でリセット）。
- **ランのデッキ**（獲得したカードを含むカードidのリスト）：試作1で既に保存の仕組みがあればそれに加える。無ければ同じように `towerRunDeckCardIds`（`List<string>`）を追加し、`SaveActiveTowerRun` で保存、`ClearActiveTowerRun` で空にする。空のときは `starter_deck.csv` から作る。戦闘開始時の山札はこのリストから作る。
- 確認用に、画面を出すたび `Debug.Log("[DeckReward] 候補: A,B / 履歴: [..] / 塔片: n")` を出す。

## 4. コンボルート（`DeckComboRoutes`、新規の static クラス。UIは結果を並べるだけ）
戦闘の仕組みのおさらい：単語を打つとその色のオーブがオーブ列（最大5）に入る。オーブは発動しても消えない。手札のカードは、オーブ列の**末尾**が色の並びと一致したら発動する。だからカード同士に次の2種類のつながりがある。

### 判定（カードA → カードB。色の並びを A、B、長さを |A|、|B| とする）
1. **同時発動**：|B| ≦ |A| で、A の末尾 |B| 色が B と同じ → A を発動させた1色で B も発動する。
2. **連結**：そうでなければ、k を |B|−1 から 1 まで大きい順に試し、「A の末尾 k 色 ＝ B の先頭 k 色」となる最初の k を使う → A の発動後、B は**あと |B|−k 色**で発動する。
3. どちらでもなければつながり無し。

### 計算する組み合わせ
- 候補カード C と、今のデッキにある**種類ごと**の各カード D（C と同じidは除く）について、**C→D と D→C の両方**を判定する。
- 並び順：①同時発動 → ②連結で「あとN色」が小さい順 → ③後ろ側のカードが攻撃ならその value が大きい順 → ④デッキの並び順（starter_deck.csv の順、追加カードは末尾）。
- 戻り値は「前のカード、後ろのカード、種類（同時／連結）、あとN色」の一覧。

### 表示
- 1行に1ルート、**最大3行**。それ以上あれば3行目の右に `+n`。
- 形式：`[宝石][宝石] 突き → [宝石][宝石] 斬撃　あと1色` ／ 同時発動は `[宝石][宝石][宝石] 居合い斬り ＋ [宝石][宝石] 突き　同時発動`（金色の文字）。名前は「・」の前の技名でよい。宝石は parts の 24px のもの（`gem_X_on_24.png`）。
- 1つも無ければ `コンボなし`（灰色）。

### 確認用の正解（今の初期デッキ10枚で計算済み）
- **突き・紅蓮（B-R）**：居合い斬り＋突き 同時発動／突き→斬撃・紅蓮 あと1色／突き→斬撃・蒼水 あと1色／`+2`（斬撃・蒼水→突き あと1色、突き→居合い斬り あと2色）
- **居合い斬り・紅蓮（R-B-R）**：居合い斬り＋突き 同時発動／斬撃・蒼水→居合い斬り あと1色／居合い斬り→斬撃・紅蓮 あと1色／`+4`
- **防御・蒼水（B-G）**：斬撃・蒼水→防御・蒼水 あと1色／防御・蒼水→防御・翠嵐 あと1色（2行だけ）
- **構え・金光（Y-R）**：構え→斬撃・紅蓮 あと1色／構え→斬撃・蒼水 あと1色／構え→居合い斬り あと2色

## 5. 画面（仮UI。見た目はあとで彩木さんがモックを作る）
1920×1080基準。今の報酬画面と同じく全画面の暗い背景の上に作る（`RunOverlayUI` に `ShowDeckReward(...)` を追加）。
- 上：タイトル「報酬をひとつ選ぶ」と通知文。右上に「デッキ n枚」。
- 中央：横に3つのパネルを中央そろえ（間40px）。
  - **カード2枚**：試作2・3で作った手札カードの表示を使い回す（彩木さんの `cursor_pack_v6C.zip` の parts、**1.2倍＝376×180**）。名前・宝石・効果文・レア枠を出す。状態タグや持ち上げは出さない。デッキに既に同じカードがあれば右上に「所持 n」。
  - **塔片パネル**：同じ大きさ（376×180）の枠に「塔片 +n」と「今の所持 m」。
- カードの下：コンボルート欄（幅376、高さ約120、3行）。
- 操作：
  - カードやパネルに**カーソルを乗せる**とコンボルートを出す（塔片はルート無し）。
  - **クリック1回**で選択状態（金の枠＋ルートを出したまま）。
  - 選択中に、もう一度クリックするか、下の「決定」ボタンで確定。
  - キーボード：`1`／`2`／`3` で選択、`Enter` で決定。
- 確定時：カードなら `ランのデッキ` に追加、塔片なら `_party.AddCoins(n)`。その後、3章の保存と `FinishCardReward()`。

## 7. 確認方法
1. デッキモードで戦闘に勝つと、カード2枚＋塔片の3択が出る。勝っただけでは塔片が増えない。
2. 1層の通常戦で、塔片パネルに「+18」と出る。選ぶと所持が18増える。
3. カードを選んで次の戦闘に入ると、山札＋手札＋捨て札が11枚になり、試作2の枚数チェックでエラーが出ない。
4. 10回続けて勝ったとき、Console の `[DeckReward]` ログで、どのカードも**直前2回の画面に出ていない**（候補が足りなくなったときだけ、古い画面から緩める）。塔片を選んだ回も履歴に入っている。
5. 同じカードを3枚持つと、そのカードは候補に出ない。
6. エレベーターで帰還して再開しても、履歴と獲得カードが残っている。全滅すると両方リセットされる。
7. 4章の「確認用の正解」と同じルートが、同じ順番で出る。
8. `UseDeckMode = false` にすると、今までの刻印報酬画面に戻る。
